## 1. الإذن الصريح وحدوده
قال المالك: «نعم حذف مساحة العمل». هذا إذن حذف النسخ المحلية ومخرجات العمل للمشروع في النطاق أدناه، ويحل محل منع حذفها في ورقة R2. لا تطلب الإذن مرة أخرى لهذه المسارات بعد استيفاء التحقق.
لا يعني الإذن حذف /home/user نفسه، أو ملفات المنصة أو بيئتها أو إعداداتها أو مفاتيحها، أو ملفات مجهولة النسبة للمشروع. لا حذف من المستودع ولا تغيير main أو PR أو محرك مقفل أو بيانات أصلية بعيدة.

## 3. قائمة الحذف المصرح بها لهذه الورقة
المجلدات المحلية التالية فقط، بمحتوياتها، بعد فحص ملكيتها والتحقق من حفظ الأدلة:

إذا لم يوجد مسار، سجله ALREADY_ABSENT ولا تحذفه بالاسم البديل. إذا كان symlink أو يقع resolved_path خارج /home/user، أو يشير إلى أدوات المنصة، لا تتبعه ولا تحذف هدفه؛ سجل الاستثناء.
احتفظ بهذه الورقة والتوكن اللازم للنشر خارج قائمة الحذف أو في الذاكرة فقط. لا تضع نسخة في مجلد سيحذف. لا تغيّر متغير HOME.

## 4. عزل العمل الجاري
افحص وجود عامل قياس أو تجهيز أو ناشر يستخدم المسارات الثلاثة. هذه الورقة لا تسمح قتل عمليات مجهولة أو قطع تجربة نشطة. إذا وجدت عاملًا حيًا تابعًا للمشروع، انتظر نهايته المعلومة أو سجل العائق الحقيقي؛ لا تحذف تحته.
استخدم قفل استرداد واحد متاحًا بالمنصة أو في الذاكرة؛ لا تنشئ ملفًا جديدًا عند تجاوز الحارس. لا عاملان للحذف والنشر.

## 5. جرد في الذاكرة دون زيادة المساحة
اقرأ أسماء الملفات وأحجامها ونوعها ومواقعها، واحسب SHA256 وGit blob SHA للملفات عند الحاجة قراءةً متتابعة. لا تنزل المستودع أو مصادر السوق أو أرشيفات قديمة، ولا تثبت حزمًا، ولا تنشئ ZIP أو نسخة backup على القرص.
يشمل الجرد جميع ملفات قائمة الحذف، لا أكبر10ملفات فقط. سجّل سبب نسبة المجلد للمشروع. لا تُفتح محتويات الملفات غير اللازمة للنسبة/الحفظ.
احسب before_bytes بالمنهج الذي أنتج تقرير المساحة؛ افصل الحجم المنطقي عن استخدام القرص إن اختلفا. لا تقيس مجلدًا جديدًا بدل الجذر الحقيقي.

## 6. حفظ الأدلة قبل الحذف — ترتيب واحد لكل ملف
صنف كل ملف في القائمة:
- نسخة موجودة أصلًا بالمستودع: طابق Git blob SHA المحلي مع الملف البعيد عند commit ثابت. احفظ مساره ومعرف الالتزام والبصمة. الاسم المتشابه أو الحجم المتساوي لا يكفي.
- نسخة مكررة محليًا: إذا تطابق SHA256 والحجم تمامًا، احفظ المحتوى الفريد مرة واحدة واربط جميع المسارات بنفس الإيصال. لا تفترض أن run وrun-final متساويان.
- كود أو تقرير أو نتائج أو raw أو checkpoint غير منشور: ارفعه إلى وجهة الاسترداد أدناه، واقرأ البايتات البعيدة عند commit ثابت وتحقق من البصمة قبل حذف الأصل.
- cache أو مدخل قابل لإعادة البناء: وثّق مصدره المثبت ووصفة إعادة بنائه وبصمة ما تعتمد عليه النتائج. إن تعذر إثبات إعادة البناء أو علاقته بالأدلة، عامله كمحتوى فريد واحفظه.
- ملفات مصادقة أو بيئة أو إعداد منصة: لا ترفعها ولا تحذفها ضمن هذه الورقة. إن ظهرت داخل المجلدات المحددة، استثنها وحدد أثر ذلك على حذف المجلد؛ احذف الملفات المصرح بها فقط. الكود الذي يحتوي سرًا يُحفظ منقحًا مع بيان التنقيح وبصمة الأصل، ولا يوضع السر في المستودع.

لا تُحذف نسخة الملف الفريدة إلا إذا ثبت حفظ محتواها أو مصدر إعادة بنائها، وسُجل الإيصال البعيد. لا يكفي إنشاء commit محلي أو رد HTTP غير متحقق منه. إذا فشلت المصادقة أو الرفع أو البصمة، يبقى الملف الأصلي ويُسجل العائق.

## 7. نقل محدود لا يحتاج مساحة قرص
قراءة الملفات الموجودة ليست تنزيلًا جديدًا. معالجة ملف أو جزء واحد في الذاكرة؛ المكتبة القياسية فقط. يمكن رفع الملفات النصية الصغيرة مباشرة عبر Git Data API.
للملفات الثنائية الكبيرة، استخدم أجزاء محتوى مستقلة لا تزيد على4000000بايت خام، وضغطًا حتميًا في الذاكرة. manifest يذكر مسار الأصل وحجمه وبصمته، وترتيب الأجزاء وحدودها وبصمة كل جزء مضغوط وغير مضغوط، ووصفة إعادة التجميع. لا تغيّر القيمة الخام العلمية.
لا تنشئ أرشيفًا محليًا؛ ولا تنقل ملفات إلى مكان آخر لإخفائها من محاسبة الحجم. لا ترفع الجزء إلى main. قراءة التحقق البعيد لكل جزء في الذاكرة فقط، ثم مقارنة بايتاته أو SHA256. احتفظ بالمصدر المحلي حتى تتأكد من جميع أجزائه.
لا نشر لكل صف تجربة؛ نقل مجمع مع ناشر واحد وتباعد معقول واحترام Retry-After. إذا استغرق الاسترداد وقتًا، استمر في المقدمة ولا تنهِ الدور بادعاء استمرار خلفي.
إذا منع حارس المنصة عملية النقل عند امتلاء المساحة، سجّل العملية والخطأ الفعلي ولا تتجاوزه، ولا تحذف أدلة غير محفوظة.

## 10. تنفيذ الحذف بعد التحقق
