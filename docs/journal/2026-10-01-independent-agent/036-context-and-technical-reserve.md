# Context budget, source economy and bounded technical reserve

Owner requested fixes to context growth/limit and missing fallback, without paid upgrades or more credential benchmarks.

- OpenCrabs v0.5.4 is explicitly configured for 240,000 context tokens (provider and agent), with its existing automatic compaction and 8,192 generation tokens. Atria's official docs advertise a 256K combined input/output context. The chosen budget leaves output headroom; it is not infinite memory or a model identity guarantee. Remote streaming silence tolerance is explicitly 300 seconds; an active streaming response has no OpenCrabs total wall-clock timeout. No provider inference was used to verify these settings.
- Resume instructions now read fresh pinned-main constitution once, then follow its actual required sequence. Duplicate filesystem/GitHub reads and unsolicited full historical bundles are discouraged. Required constitutional sources are not omitted. Repository reads accept an exact commit and explicit inclusive line ranges or final N lines, with bounded source/output sizes and original line provenance. A large input count is not by itself proof of hallucination or generated output consumption.
- Interactive requests reach a small authenticated loopback relay, which calls the slot4-only gateway alias, then the slot7-only alias once on network failures, HTTP401/402/403/408/429 or5xx. Bad input/context overflow does not trigger the reserve. Automatic gateway retries/fallbacks are disabled in the pinned production overlay. A received successful upstream response is never replayed after a stream interrupts. Interrupted streams emit an explicit error instead of claiming completion. Slot7 is a backup credential at the same provider, not a separately hosted provider; shared outages/quota remain possible. Direct advice/benchmark slot ordering is unchanged.
- `nova_repo_runtime` exposes fixed non-secret installed settings and last observed request usage metadata. Provider usage counters remain unavailable until emitted. Concurrent requests cannot mix usage counters. Neither credentials, prompt bodies nor reasoning are stored in this diagnostic. A two-request concurrency gate, 4MiB request cap and bounded response reads limit relay memory. Existing cgroup memory monitoring now includes relay RSS. Actual Render RAM after deployment still requires observation; no paid tier or service duplication is introduced.

Validation: all 152 local tests pass, including a real loopback HTTP/SSE fixture proving slot4->slot7, exact stream forwarding, and no replay after stream truncation; mocked technical/nontechnical failures; immutable source routing; context/output headroom; ranges pinned to a commit; and secret-free runtime metadata. No real API request, key benchmark, trade, main merge or PR performed. Render deployment and a normal owner message are the remaining live verification.

Primary references checked: https://api.atria-asi.ai/docs and https://github.com/opencrabs/opencrabs/blob/v0.5.4/config.toml.example , plus v0.5.4 compaction implementation/tests. These are configuration/transport fixes; they cannot guarantee error-free model reasoning. Arithmetic and source provenance checks remain required.
