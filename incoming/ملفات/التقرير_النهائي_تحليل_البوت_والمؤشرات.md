# ⚠️ 0) تنبيه أمني عاجل (اقرأه قبل أي شيء)

في ملف التشغيل `start_zero.sh` توجد **مفاتيح حقيقية مكشوفة كنصّ صريح** في السطر 8–11:

**الخطر:** أي شخص يصل للملف/السكربت تصل له مفاتيحك. حتى لو كان على Testnet الآن، المفاتيح نفسها قد تُستخدم لحساب حي لاحقاً.

**الإجراء المطلوب (مهم جداً):**

هذا **أهم** تعديل في كل التقرير. ✅

# 📋 1) تشخيص حال البوت الفعلي

## ما هو NOVA فعلياً؟
بوت اسكالبينج (نطاق دقائق/ثوانٍ) على Binance Spot، يستهدف **صعود السعر** فقط (Long) وكسوراً صغيرة (0.3%–3%). يعمل على Android عبر Termux، لكنه **يستخدم REST API** وليس WebSockets.

## مقارنة: «المخطط المتفق عليه» مقابل «الكود الفعلي»

| المكوّن | المخطط (Blueprint) | الكود (NOVA.py) الحالي | الحالة |
|---|---|---|---|
| تدفق البيانات | WebSocket (kline_1m / aggTrade / bookTicker) | REST API مع تخزين مؤقت | ❌ **لم يُنفَّذ** (الوديبل الأسرع غير مطبق) |
| فلتر الاتجاه | ALMA(200) | ❌ غير موجود | ❌ **مفقود** |
| فلتر الزخم | RSI(14) > 50 | ❌ غير موجود | ❌ **مفقود** |
| Premium/Discount Zone | قياس القمة/القاع لآخر 50 شمعة | ❌ غير موجود | ❌ **مفقود** |
| المقاومة الديناميكية | SMA(20)+2×ATR | ATR الحالات | ⚠️ **جزئياً** |
| Quantized Epsilon Band | تصفية التذبذب الوهمي | ❌ غير موجود | ❌ **مفقود** |
| Swing Death | منع القيعان المستهلكة | ❌ غير موجود | ❌ **مفقود** |
| Six-Factor Scoring | تقييم 0–100 لحجم الدخول | ❌ غير موجود (حجم ثابت) | ❌ **مفقود** |
| Order Flow (aggTrade) | نسبة مشترين لحظية >58% | اختلال دفتر الأوامر (depth) فقط | ⚠️ **جزئياً/بديل** |
| بنية السوق MSS | ✅ | ✅ موجود | ✅ **مطبَّق** |
| FVG | ✅ | ✅ موجود | ✅ **مطبَّق** |
| وقف الخسارة | 1.15×ATR | عبر `strict_stop_target` | ✅ مطبَّق |
| قفل التعادل | ربح +0.5% | ✅ | ✅ مطبَّق |
| تتبع الأرباح | 1.5×/1.2× ATR | ✅ عبر OCO | ✅ مطبَّق |
| Time Stop | 60 ثانية | ✅ | ✅ مطبَّق |
| حاكم العملة | 3 خسائر → إيقاف 10د | ✅ | ✅ مطبَّق |
| منع العملات النائمة | ATR/VLR | ✅ | ✅ مطبَّق |

**الخلاصة:** الكود الحالي هو **~40%** من المخطط. الجزء الأهم المطبق هو «إدارة المخاطر» و«بنية السوق MSS+FVG». لكن **طبقة الفلاتر الكلية (ALMA/RSI/Premium) وطبقة الذكاء الكمي (Epsilon/Swing/Scoring) وطبقة WebSockets غير مطبقة** — وهذه هي «الحرب» التي سنكسب بها.

| العنصر الحالي | المشكلة | البديل المقترح |

# 🌟 3) ما نُضيف — ترشيح المؤشرات من المكتبة الكبيرة

عندي 45+ تقنية في قاعدة المعرفة. **رتبتها:** (أ) قوية ومطلوبة، (ب) مفيدة بشروط، (ج) نستبعدها. القاعدة: **لا نضيف تقنية إلا إذا تزيد دقة القرار الحقيقي — وإلا تُستبعد لتقليل الضوضاء.**

## الفئة (أ) — نضيفها (أعلى قيمة، تناسب اسكالبينج الدقيق)

| # | التقنية | لماذا؟ |
|---|---|---|
| A1 | **WebSocket aggTrade** (تدفق أوامر حقيقي) | بنية المكتبة كلها تتطلب delta حقيقية (`+/-q` حسب `isBuyerMaker`). هذا يفتح كل منهجيات التدفق |
| A2 | **فلتر الاتجاه ALMA** (من المخطط) | فلتر بوابة خفيف يمنع الشراء تحت خط الاتجاه |
| A3 | **فلتر الزخم RSI(14)** | يمنع الدخول عندما يكون الزخم ضعيفاً/ميتاً |
| A4 | **Premium/Discount Zone** (من المخطط) | يمنع الشراء في أعلى 50% من النطاق (منطقة هشّة) |
| A5 | **Quantized Epsilon-Midpoint Band** | الفاصل الزمني الأعلى قيمة في المكتبة — يصفّي «التذبذب الوهمي» الذي يخدع المؤشرات. **حارس البوابة الأهم** |
| A6 | **Swing Death / Touch Count** | يمنع الشراء من قيعان استُهلكت سيولتها (ابتداءً من اللمسة الثالثة) |
| A7 | **Six-Factor Scoring** (تقييم 0–100) | يحوّل القرار من «نعم/لا» إلى حجم ذكي (0% / 50% / 100%). **يضاعف الربح الحقيقي** عبر تحجيم حسب الثقة |
| A8 | **Liquidity Sweep / SFP / Equal-Level Family** | أقوى محفّز لانعكاس في المكتبة (سحب السيولة قبل الصعود) — يكمل MSS رائعاً |
| A9 | **نظام بنية السوق الكامل** (BOS/CHoCH + Displacement 0.6×ATR) | يضيف تأكيد قوة الكسر، وأفضل من MSS الحالي (الذي يكتفي بالفحص بسيط) |
| A10 | **Block Volume Profile (POC/VA)** | يُبيّن منطقة القيمة والأسعار السيئة للدخول |
| A11 | **فلتر التقلب السعر (Percentage Volatile)** | يوقف التداول أثناء الذروة/الهدوء الشديد |
| A12 | **Micro-divergence** (انحراف RSI في نطاقات أوّلية) | إشارة انعكاس أقوى |
| A13 | **نظام جلسات + Killzones** | أوقات السيولة الحقيقية (بالوقت) — يحسّن الدخول الكبير |

## الفئة (ب) — مفيدة لكن بشرط (تُفعَّل تدريجياً، لا كلها معاً)

| التنبيه | ملاحظة |
|---|---|
| **Order-Block مكتبة** | قوي، لكن يحتاج تنفيذ lifecycle (Mitigated/Breaker). نفعّلها مرحلة لاحقة |
| **VWAP / session VWAP Z-score** | إشارة إرجاع للمتوسط، مفيدة عند حاجتها ولا تأكل الموارد |
| **TTM Squeeze / Coil** | يُنصح كملحق فقط (لتوقع التمدد) لا كإشارة أساسية |
| **Structural FSM (سويب/MSS/تأكيد)** | الأقوى (وصفها في أعلاه). يدمج A8/A9 |
| **ZLEMA / Ma-Stack** | بديل إضافي للاتجاه، لا نضيفه فوق ALMA إلا إذا أثبت تفرّداً |

## الفئة (ج) — نستبعدها (تشتت/تكرار/تسريب)

- ❌ **MACD / MACDV / Stochastic / Bollinger وحدها:** متأخرة أو مكررة — أمامنا RSI + Volatility يكفيان.
- ❌ **Heiken Ashi كإشارة:** متأخرة، يُستخدم للعرض فقط.
- ❌ **مؤشرات النمذجة المعقدة كإشارة أساسية** (Harmonic XABCD، Elliott، k-NN ECHO، Naive-Bayes، Kalman): رياضياً جميلة، لكنها على شموع الدقيقة قد تُدخل **overfitting** وتستهلك موارد الهاتف. نستبعدها كإشارة، ويجوز إضافتها لاحقاً كتأكيد **إذا أراد المستخدم**.
- ❌ **كل تقنيات التصفية الزائدة** (Σ-filters، 18-flavor filter-library، SuperTrends متعددة): معظمها يعيد حساب نفس فكرة «الاتجاه»؛ نختار **أفضل نسخة واحدة** (ALMA).
- ❌ **Parabolic SAR وMomentum وكل ما يكرر RSI/MACD.**
- ❌ **Anything "REPAINTING"** — غير قابل للتداول لحظياً.
- ❌ **الإشارات التي تُعيد رسم نفسها** (لا تُستخدم في بوت لحظي).

# 🏗 4) الصورة النهائية المقترحة (المعمارية الجديدة)

```
        ┌──────────────────────────────┐
        │  WebSocket Data Pipeline     │  ←  aggTrade + kline_1m + bookTicker
        └──────────────┬───────────────┘
                       │
  ┌────────────────────▼────────────────────┐
  │  MACRO FILTER (حارس البوابة)            │
  │  • ALMA(200) الاتجاه  •  RSI(14)>50     │
  │  • Premium/Discount Zone (≤50%)         │
  │  • Epsilon-Midpoint Band (منع الضوضاء)   │
  │  %R?  →  رفض  ✓  →  تابع                 │
  └────────────────────┬────────────────────┘
                       │
  ┌────────────────────▼────────────────────┐
  │  QUANT LAYER (تشديد)                     │
  │  • Swing Death (منع القيعان المستهلكة)    │
  │  • Volatility Filter (منع الهدوء/الجمود)  │
  │  %ر?  →  رفض                             │
  └────────────────────┬────────────────────┘
                       │
  ┌────────────────────▼────────────────────┐
  │  MICRO TRIGGER (محفّز الدخول)            │
  │  • Liquidity Sweep/SFP  →  MSS/BOS       │
  │  • FVG Zone Tap  +  Order Flow (>58%)    │
  │  →  إشارة دخول                            │
  └────────────────────┬────────────────────┘
                       │
  ┌────────────────────▼────────────────────┐
  │  SCORING + SIZING (حجم ذكي)              │
  │  Six-Factor Score → 0% / 50% / 100%      │
  └────────────────────┬────────────────────┘
                       │
  ┌────────────────────▼────────────────────┐
  │  RISK MANAGEMENT (صارم — موجود فعلاً)     │
  │  stop/target/trailing/breakeven/timestop │
  └──────────────────────────────────────────┘
```

**الأساس الذي لن يمسّ:** إدارة المخاطر الموجودة (ممتازة) + MSS/FVG.

# 🧠 6) ملخص القرارات التي نحتاجها منك (قبل أي كود)

1. **المفاتيح:** هل سنبدأ بإلغاء/تجديد مفاتيح الـ API (لأمان حسابك)؟
2. **WebSockets:** أوافق على نقل تدفق البيانات من REST إلى WebSocket (أسرع + يحل مشكلة الحظر)؟
3. **نطاق الفلاتر:** نكتفي بالـ 4 فلاتر الأساسية (ALMA، RSI، Premium، Epsilon) لتجنب التشتت؟ أم تريد إضافة Swing Death وVolatility أيضاً؟
4. **حجم الدخول:** نفعّل Six-Factor Scoring (حجم ذكي بثقة 0/50/100%) بدل الحجم الثابت؟
5. **المؤشرات المعقدة** (Harmonic/Elliott/kNN/Naive-Bayes): نستبعدها نهائياً من المرحلة الحالية (موصى به) أم تريدها كتأكيد لاحقاً؟

> ⚠️ **لا أبدأ أي تعديل قبل ردّك على هذه النقاط.** بناءً على إجاباتك، ننفّذ المرحلة التالية.
