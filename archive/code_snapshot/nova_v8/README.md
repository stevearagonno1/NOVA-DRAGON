# NOVA_V8 — Research-first adaptive quant trading bot

NOVA_V8 هي بوت تداول كمّي (Python 3.10+ / Termux-ready) مبنيّ **بمنهج البحث أولاً**:
نختبر الاستراتيجيات على بيانات تاريخية حقيقية، وعندما تثبت فاعلية أيّ نمط فقط عندها يُنقل
إلى البوت المباشر. هذه الحزمة تنفّذ **مرحلة البحث/الاختبار الرجعي** كاملةً وليس التداول
المباشر (Live is intentionally not implemented yet).

> **لا توجد بيانات في هذه الحزمة.** ضع بيانات الشموع الدقيقة (1m) في مجلد الأرشيف ثم شغّل.

---

## التشغيل السريع / Quick start

```
pip install -r requirements.txt

python -m nova_v8 doctor        # ملخص البيئة والإعدادات (بلا بيانات)
python -m nova_v8 selftest      # فحص ذاتي كامل على بيانات تركيبية
python -m nova_v8 available     # ما هو موجود في الأرشيف
python -m nova_v8 research      # البحث + التقارير + إشعارات تيليجرام
python -m nova_v8 status        # إعادة إرسال آخر تقرير محفوظ
```

خيارات `research`:

```
--symbols BTCUSDT,SOLUSDT     # تحديد عملات
--triggers RSI,EMA            # تحديد محفّزات (أو all)
--start 2021-01-01 --end 2026-01-01
--trail-basis atr|fib         # أساس التتبّع (افتراضي fib)
--experiment baseline         # اسم التجربة (يُسجَّل في CSV)
--out ~/nova_v8_out           # مجلد المخرجات
--strategies core|all|...     # core افتراضياً؛ all يشمل الاستراتيجيات المنفصلة
```

### أعمدة CSV المهمّة
`category, kind, symbol, regime, trigger, side, entry_bar, exit_bar, bars_held,
net_frac, pnl_usd, reason, cycles, success, entry_px, entry_ref_px,
entry_cost_pct, exit_px, mult, experiment, series, snapshot`
حيث `entry_px` هو سعر الدخول التنفيذي التقديري بعد تكلفة السوق، و`entry_ref_px` هو
سعر افتتاح الشمعة المرجعي قبل التكلفة، و`entry_cost_pct` يوثق تكلفة الدخول.
أما `snapshot` فهو JSON لقراءة المؤشرات عند شمعة القرار، و`mult/series` لتتبّع
سلسلة الحصد والتضاعف (فصل 6).

## تقرير الحالة (الصيغة المعتمدة)

```
📊 التقرير العام
🟢 الناجحة: X%   🔴 الخاسرة: Y%   إجمالي المكاسب: Z $   نسبة النجاح: W%
🟦 نمط الشبكة (Grid) — عدد الشبكات المغلقة: N · ناجحة: a% · صافي: b$
🟧 تابعات البيتكوين (BTC) — عدد الصفقات: M · ناجحة: c% · صافي: d$
⏱️ ملاحظة زمن الاستجابة (قيد حيّ): متوسط عمر الإشارة · نسبة تداخل الصفقات
```

## أوضاع التشغيل / Modes

1. **اتجاهي (صاعد/هابط):** محفّزات (أول من يطلق يفوز) + محرّك خروج ATR/فيبوناتشي.
2. **شبكة (عرضي):** شبكة Spot وحدها بلا مؤشرات؛ تُغلق عند خروج النطاق أو نهاية الحالة.
3. **تابعات البيتكوين:** شراء التابعين المتأخّرين، بعد تأكيد صعود BTC + كسر بنيوي.
4. **متفجّر:** لا تداول (انتظار الاستقرار).

### محرّك الخروج
- وقف صلب متكيّف ATR (1.15× ضمن 0.30–3.0%).
- قفل تعادل عند ربح ≈1×ATR.
- **تتبّع فيبوناتشي (الافتراضي الآن):** يحمي نسبة من أفضل موجة ربح — يعطي 0.618 ثم
  يضيّق إلى 0.382 عند نموّ الربح. يمكن التبديل إلى تتبّع ATR الكلاسيكي
  بـ `--trail-basis atr` أو `NOVA_TRAIL_BASIS=atr`.
- وقف زمني ≈ شمعة واحدة (مع مدة سماح عند تتابع الإشارات).
- **قيم لكل حالة سوق:** `REGIME_EXIT_OVERRIDES` في `config.py` — فارغة الآن (ملف موحّد)،
  جاهزة للمعايرة لكل حالة لاحقاً.
- **الوقف عند القفزة:** إذا فتحت الشمعة عبر مستوى الوقف يُنفَّذ عند **سعر الفتح**.

### نموذج التكلفة والتنفيذ (واقعية محافظة)
- الدخول الاتجاهي وBTC يتم عند افتتاح الشمعة التالية، لا عند سعر الإشارة.
- Directional وBTC: عمولة 0.1% + **Effective execution cost** عند الدخول والخروج؛
  التكلفة الأساسية 0.03% لكل جهة، وتتسع ×2 عند VR مرتفع و×3 في Shock.
- Grid داخل النطاق: أوامر Limit عند المستوى مع العمولة فقط؛ التصفية الإجبارية
  عند كسر النطاق تعامل كأمر سوقي بتكلفة متغيرة.
- إذا فتحت الشمعة عبر الوقف، يكون الأساس هو **سعر الافتتاح** ثم تطبق تكلفة التنفيذ
  المحافظة، لا مستوى الوقف القديم.
- هذا تقدير محافظ يجمع تقريباً أثر السبريد والانزلاق؛ وليس قياساً حقيقياً لدفتر
  الأوامر.
- **حساسية التنفيذ:** تقرير نقطة الانقلاب عند 0.03/0.10/0.30% للأوامر السوقية.

## النسبة الذهبية / Fibonacci — كيف طُبِّقت

استُخدمت في **المواضع المبرَّرة فقط** (لا في أطوال المؤشرات):
- تتبّع الخروج: نسبة من موجة الربح (`FIB_RETRACE_P1/P2`).
- مرجعها علميّ في التحليل الفني (تراجعات 0.618/0.382) وليست تركيباً رقمياً.

## الحماية والاستقرار / Stability & Protection

- لكل وحدة هوية مستقلة في `strategy_registry.py`: Directional وGrid وBTC، مع
  تسجيل منفصل للاستراتيجيتين مستقلتين `long_cycle` و`market_open` دون تفعيلهما في Baseline.
- `risk.py` يراجع التعرض الإجمالي، تصادم العملات، حدود الاستراتيجية، عدد الصفقات،
  السحب الرأسمالي وحد الخسارة اليومية. الوضع الافتراضي `audit` لا يغيّر نتيجة
  Baseline؛ الوضع `strict` متاح لمحاكاة محفظة محمية.
- كل سجل يتضمن وقت الدخول والخروج، الاستراتيجية، القيمة الاسمية، وحالة الحارس.
- فحص جودة البيانات يسجل OHLCV غير الصالح والفجوات قبل البحث؛ يمكن تفعيله بوضع
  `strict` قبل التشغيل الورقي.
- لا يوجد تداول حي أو رافعة؛ `LIVE_TRADING_ENABLED=False` مقصودة.

## ملاحظات صادقة

- نتيجة الاختبار الذاتي (بيانات تركيبية) **ليست** مؤشراً على الربحية.
- الاختبار الرجعي جيد لاكتشاف ما **لا** ينجح؛ أي نتيجة إيجابية = **فرضية** تُختبَر خارج
  العيّنة (سنة لم تُلمس) وبانزلاق متشائم قبل تصديقها.
- التجارب على التاريخ الحقيقي وضبط المتغيّر الواحد ومرحلة التعلّم **مؤجّلة** حتى توفّر
  البيانات.
- استراتيجيتا `long_cycle` و`market_open` أصبحتا وحدتين بحثيتين منفصلتين؛ لا تدخلان
  Baseline افتراضياً. شغلهما صراحة عبر `--strategies long_cycle,market_open` أو
  `--strategies all` بعد توفير البيانات.
