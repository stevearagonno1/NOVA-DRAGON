# §2 المعمارية غير المتزامنة (Async / الأحداث)

**الهدف:** لا يحجب أي مكوّن الآخر؛ التليجرام لا يوقف تدفق الأوامر، والعكس.

**نموذج التنفيذ (single event loop, asyncio):**

```
[event loop]
 ├─ Task A: WebSocket klien kline_1m   (قراءة الشموع)
 ├─ Task B: WebSocket aggTrade          (تدفق الأوامر + delta)
 ├─ Task C: WebSocket bookTicker        (أفضل عرض/طلب)
 ├─ Task D: حلقة الفحص/الماكرو           (يستهلك مخرجات A/B/C)
 ├─ Task E: حلقة التليجرام (aiohttp)     (أوامر المستخدم + رسائل)
 └─ Task F: إدارة المراكز + التنفيذ
```

**قواعد الحاكمة:**
- كل مهمة `asyncio.Task` منفصلة.
- التواصل بين المهام عبر **قنوات/صفوف غير حابسة** (`asyncio.Queue` + حالة ذرّية مشتركة).
- **التليجرام لا يلامس WebSockets أبداً** — فقط يقرأ الحالة المشتركة ويرسل عبر جلسة `aiohttp`.
- `aiohttp` للـ WebSocket وللتليجرام معاً نفس العميل (بدل `urllib` و`requests`).

| القناة | المصدر | الإخراج |

## المخرجات الحاسمة (من `aggTrade`)
- **CVD** (السيولة التراكمية): `CVD += delta`.
- **نسب مشترين/بائعين** لحظية.
- تُغذّي Naive-Bayes (§5.2) وSix-Factor (§7) وفلتر التدفق.

- تخزين حد أقصى (FIFO) لكل سلسلة + `TTL`.
- `rolling_max/min`, `rolling z-window(50)`, `EMA50` — كلاهما O(1).

# §4 فلاتر الماكرو (حارس البوابة) — كلها تُمرّر السعر لتنتقل للإشارة

## §4.1 فلاتر الاتجاه — Anchored Powered KAMA + Welford σ
**المصدر:** KB §1.2.
- `anchor` = بداية الجلسة.
- `ER = |p − anchor| / Σ|Δp|` (كفاءة الحركة منذ الجلسة)؛ `SC = ER²`.
- `kama = SC·p + (1−SC)·kama_prev`.
- Welford: `sigma = √(Σ(p−kama)²/n)` — O(1)، لا يخزّن نوافذ.
- **قرار الاتجاه:** `sign(p − kama)`؛ **القوة:** `|p−kama|/σ`.
- **القاعدة:** يُرفض الشراء إذا كان `p < kama` (الاتجاه أسفل) أو إذا كانت القوة أقل من عتبة (`STRENGTH_MIN = 0.5σ` مثلاً) — يمنع الدخول في تذبذب ميّت.

## §4.2 Premium/Discount Zone
**المصدر:** المخطط + KB §1.19.
- `highest_high` و`lowest_low` لآخر 50 شمعة (أو نافذة الجلسة).
- `position% = (p − low) / (high − low) × 100`.
- **القاعدة:** يُرفض الشراء إذا كان `position% > 50` (نصف علوي = منطقة غالية). الشراء مسموح في `≤50%`.

## §4.3 Quantized Epsilon-Midpoint Band
**المصدر:** KB §1.1.
- `h = max(close,200)`، `l = min(close,200)`، `eps = 2.8 × ATR_prev`، `m = منتصف`.
- تكون الأصباغ من الشمعة **المغلقة السابقة** (لا same-tick flip-flop).
- كلما اخترق السعر `m±eps` خطوةً إلى الأعلى/الأسفل ⇒ **حقيقة الـ state**.
- **القاعدة:** لا تفعيل فحص MSS/FVG إلا إذا **خطوة الـ state فعلياً** (أي اخترق السعر الحزام). يصفّي التذبذب الوهمي.

## §4.4 Volatility Filter
- يمنع التداول في: (أ) تقلب شديد (`ATR% > PERCENTILE95`)، (ب) تقلب ميت (`ATR% < PERCENTILE5`)، (ج) جمود السوق (CVD مسطّح).
- **نسبة/مضمون:** يقرأ ويعيد الجدول حسب كل عملة، وبعناصر خطية أصيلة من المكتبة.

# §5 طبقة الذكاء الكمي (التشديد)

## §5.1 Swing Death / Touch Count
**المصدر:** المخطط + KB §3.7/§3.8.
- يُحتفظ بسجل القمم/القيعان (registers).
- يعُدّ اللمسات لكل قاع/قمة؛ عند **اللمسة الثالثة** ⇒ يُعلن "Swing Death" (مستوى مستهلَك السيولة) ويُحظر الشراء منه عائداً بشكل دائم حتى يصعد الزخم.

## §5.2 Naive-Bayes Order-Flow Classifier (بفيتو `Diverged`)
**المصدر:** KB §4.11 — **أساسي (لن يُستبعد)**
- **ميزات لكل بار (وريث من قبل tick في البورت):**
  - `delta` الحقيقي من `aggTrade` (لا نستبدل بالـ wick-split bar).
  - `CVD`؛ `cvdRoc`؛ `priceRoc`؛ `slopeR`؛ ثم `F1/F2/F3 = z50(...)` (z-score نافذة 50).
- **التدريب الآلي** — مجاميع تشغيلية فقط (لا عينات مخزّنة): `(n_c, ΣF_k, ΣF_k²)` ⇒ `mu, σ` لكل تصنيف، و`prior`.
  - `Bull` = السعر وCVD صاعدان معاً؛ `Bear` = كلاهما هابط؛ **`Diverged` = اختلاف (فئة «منع التداول» صريحة، ليست فرعلة).**
  - `posterior_c = prior · ∏ N(F_k; mu, σ) / normalizer`.
  - Warm-up بعد 100 بار مسمّى.
- **القواعد:**
  - `long = posterior_Bull ≥ 0.70` و`close > EMA50` و`CVD > CVD[1]`.
  - **`Diverged` (الفئة الثالثة) = VETO مانع — لا تداول نهائياً** مهما كانت بقية الإشارات.
  - الطبقات: `posterior ≥ 0.85` عالية / `≥ 0.75` متوسطة.
- **المراجعة الذاتية:** معدل نجاح `argmax-posterior` مقابل النتيجة المتحقّقة — لمراقبة انحدار الجودة؛ يتحوّل بمرور الوقت (adaptation).

# §6 محفّز الدخول (Micro Trigger)

**تسلسل (TJR sweep → MSS → zone-tap):** يدمج الموارد الحالية MSS/FVG مع ميزة Sweep/SFP و**إزاحة Displacement**.

1. **SWEEP (تهيئة):** `low < SSL و close > SSL` (اختراق الذبابة + إغلاق خلفي) ⇒ "تم استخراج التعبير".
2. **MSS (تأكيد داخل 12 شمعة):** كسر المستوى مع `displacement ≥ 0.6×ATR`.
3. **FVG / Zone-Tap (إطلاق):** فجوة FVG جديدة `≥ 0.2×ATR`؛ وإلا حزام 50% من امتداد الرجل.
4. **قاعدة التدفق:** تدفق الأوامر `≥ 58%` مشترين (أو مُفعَّل من Naive-Bayes في §5.2).
5. **قاعدة الإزاحة:** `|إغلاق − فتح| > 0.6×ATR` لإغلاق الكسر (منع كسر إسفيني).

**الهدف:** 3 أقسام (Sweep→MSS→Tap) **حسب كامل FSM** — لا ننتظر، لا ننتظر تكتمل الشمعة.

# §7 Six-Factor Scoring + التخضيم الديناميكي

**المصدر:** KB §4.1 — **يُفعَّل (بدل الحجم الثابت).**

6 عوامل (صفرية=0 → 1)، ثم `Score 0-100`:
`wick` (رفض) + `atr` (عمق الاختراق) + `vol` (اندفاع الحجم، منقوص الحد حتى 2×) + `body` (إغلاق عبر المستوى) + `ema` (امتداد من الاتجاه) + `eq` (مجموعة التوقف المتحد/المتساوي).

```
score = 100 × Σ(weight_k × c_k) / Σ(weight_k)
	w = {wick:1.0, atr:1.0, vol:0.8, body:1.0, ema:0.6, eq:0.8}
```

**القاعدة (التخذيم):**
| الدرجة | الحجم |
|---|---|
| `< 50` | لا تداول |
| `50–69` | **0%** (رفض) |
| `70–84` | **50%** (نصف) |
| `≥ 85` | **100%** (كامل) |

> (الحدود `50/70/85` أُخذت من المخطط والمكتبة؛ نُنبّه أنها **قابلة للمعايرة** عبر Backtest قبل الإفراج — نتركها إعداداً، لا ثابتاً.)

# §9 نظام التليجرام — **Async** (تقرير اليوم + السجل المبوب)

## §9.1 جلسة aiohttp (غير حابسة)
- عميل `aiohttp.ClientSession` واحد — إرسال غير متزامن عبر `Task`.
- **لا يغلق الـ event loop ولا يوقف WebSockets** (يقرأ مشتركة الحالة، يرسل ويغلق).

## §9.2 الرسائل المطلوبة
| حدث | الرسالة |
|---|---|
| **دخول** | «دخول [العملة] — السعر، الكمية، **Score 0-100**، **نسبة Naive-Bayes/ثقة**، وقف/هدف/مخطط» — ⭐ نقاط الثقة لتقييم جودة الفرصة لحظياً |
| **خروج** | «خروج [العملة] — دخول/خروج، **Pure P/L**, **−عمولة**, **صافي بعد العمولة**، السبب (Stop/Target/Trail/TimeStop/Governor)» |
| **إحصائي يومي** | `build_stats_text` اليوم (تداولات، Wins/Losses، صافي بعد العمولة، أفضل/أسوأ، حاكم تحت العقوبة، الفلاتر رفضت) |
| **تقرير يومي آلي** | في `DAILY_REPORT_HOUR` مرة واحدة/يوم |

## §9.3 السجل المبوب (Pagination)
- زر `📋 سجل الصفقات` → صفحات، `◀ السابق / التالي / 🔴 تحديث / 🏠 القائمة`.
- كل صف: symbol، الوقت، دخول/خروج، كمية، خام، **−عمولة، صافي بعد العمولة**، السبب.
- تُحسب **عمولة دقيقة** (`fee_sim`): ربح صافٍ بعد رسوم Binance (~0.20% ذهاباً وإياباً).

## §9.4 لماذا Async أمر بالغ؟
تليجرام يعمل كـ **aiohttp** (لا حجب) — مثلاً: عند إرسال تقرير طويل، يستمر البوت في قراءة تدفق الأوامر وإدارة المراكز. **غير قابل للتفاوض** (حسب طلبك).

# §13 الاختبار والتحقق (قبل الإصدار الحي)

1. **Backtest** على سنة كاملة عبر ≥5 عملات (BTC, ETH, SOL, XRP, DOGE + أعلى فوليوم) — باستخدام حقول سجل صريحة (no look-ahead، repaint off).

# §15 قرارات أخيرة نحتاج اعتمادك عليها (لنبدأ التنفيذ)

1. **ماهي القيم الافتراضية للمعادلة؟** هل نبدأ بقيم المخطط/المكتبة الواردة (KAMA `power=2`, `eps=2.8·ATR`, `premium=50%`, `swing_death_touch=3`, `NB≥0.70`, `score: 50/70/85`) — ثم نعايرها في Backtest؟ أم لديك قيم مدوية؟
2. **منصة Testnet أولاً** للتطوير، ثم الحية فقط بعد Backtest —— هل أستند إلى ذلك أيضاً؟
3. **حجم الأوتار:** `~50` عملة أعلى فوليوم (كما المخطط) تُحدَّث كل 10 دقائق —— أم قائمة محددة؟
4. **ETFs/جلسة:** أنت رفضت أساساً إضافة النظام الجلسة — أم نكتفي بالـ UTC؟
5. **تقرير Net after fees:** تريده في كل رسالة — نفعل ذلك (per-trade وper-day) — مؤكد؟
6. **هل نلغي فكرة الذكاء المعقد مع العدول عن أي معايرة له مستقبلاً؟** — نحرّره كي لا ننهك التطبيق في المرحلة الأولى.

> ⚠️ **لا أبدأ M0 قبل موافقتك على هذه الوثيقة وعلى البنود §15.**
