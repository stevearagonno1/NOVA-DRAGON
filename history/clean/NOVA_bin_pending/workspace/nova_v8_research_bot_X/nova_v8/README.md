# NOVA_V8 — Research-first adaptive quant trading bot

NOVA_V8 هي بوت تداول كمّي (Python 3.10+ / Termux-ready) مبنيّ **بمنهج البحث أولاً**:
نختبر الاستراتيجيات على بيانات تاريخية حقيقية، وعندما تثبت فاعلية أيّ نمط فقط عندها يُنقل إلى
البوت المباشر. هذه الحزمة تنفّذ **مرحلة البحث/الاختبار الرجعي** كاملةً وليس التداول المباشر.

> ملاحظة مهمّة: نتائج البحث تُبنى على بيانات تاريخية لا تشملها هذه الحزمة. ضع بيانات
> الشموع الدقيقة (1m) في مجلد الأرشيف ثم شغّل البحث. تفاصيل أدناه.

---

## ما الذي يعمل الآن (المرحلة الحالية)

* **خلفية وغير مراقَبة:** تشغيل البحث في الخلفية، وعدم إرسال إلا:
  * إشعارات تقدم النسبة المئوية (10 / 25 / 50 / 75 / 90 / 100%)
  * **تقرير حالة نهائي واحد** عند اكتمال كل شرط.
* **وضع البحث فقط** — لا يوجد أيّ تبديل تفاعلي لصفقة حيّة (التداول المباشر لاحقاً).

### أوضاع التشغيل الثلاثة (تُقيَّم في الاختبار الرجعي)
1. **التداول الاتجاهي (اتجاهي):** صفقات طويلة في سوق صاعد وقصيرة في سوق هابط، مدفوعة
   بمجموعة محفّزات (first-to-fire)، مع محرّك خروج يعتمد على ATR
   (وقف حماية / قفل ربح / تتبّع مرحلي / وقف زمني).
2. **شبكة سعرية (شبكة):** عندما تتحوّل الحالة إلى «عرضي» تُفتح شبكة تلتقط التذبذب ضمن نطاق.
3. **تابعو البيتكوين (بيتكوين):** شراء الاتجاه الصاعد للعملات المتأخّرة ذات الارتباط
   العالي بالبيتكوين بعد تأكيد صعود BTC + كسر بنيوي MSS على العملة.

### تقرير الحالة مقسّم لثلاثة أقسام (كما اعتُمد)
* 📊 **التقرير العام**: صفقات الاتجاهي — 🟢 نسبة الربح + 🟥 نسبة الخسارة +
  💵 إجمالي المكاسب + ✅ نسبة النجاح.
* 🟦 **قسم الشبكة**: عدد الشبكات المغلقة · نسبة النجاح · الصافي.
* 🟧 **قسم تابعي البيتكوين**: عدد الصفقات · نسبة النجاح · الصافي.

## خطوات الاستخدام

### 1) ضع البيانات التاريخية
التنسيق المطلوب: **ملفات Parquet** لكل عملة، واحدة لكل دقيقة، في مجلد الأرشيف (الافتراضي
`~/crypto_archive`). الاسم:

```
SYMBOL_1m.parquet        # مثال: BTCUSDT_1m.parquet
```

يجب أن يحتوي الملف أعمدة زمن (`open_time`/`timestamp`...) وأعمدة
`open, high, low, close, volume`. تُفهم الأسماء التاريخية تلقائياً
(TONUSDT←GRAM، RENDERUSDT←RNDR).

### 2) تحقّق سريع بدون بيانات
```
python -m nova_v8 selftest
```
يُنشئ بيانات تركيبية صغيرة ويشغّل كل أوضاع المحرّك + فحوصات حسابية على
الشبكة ومحرّك الخروج، ويتأكّد من عدم وجود استثناءات.

### 3) شغّل البحث
```
python -m nova_v8 available     # اعرض ما هو موجود في الأرشيف
python -m nova_v8 research      # نفّذ البحث + التقرير + إشعارات تيليجرام
python -m nova_v8 status        # أعد إرسال آخر تقرير محفوظ إلى تيليجرام
```

المخرجات في مجلد المخرجات (الافتراضي `~/nova_v8_out`):
* `research_results.csv` — سجلّ صفقة/وحدة واحد لكل سطر (الاتجاهي/الشبكة/بيتكوين).
* `final_report.txt` — تقرير الحالة النهائي (الأقسام الثلاثة).
* `oracle_stability.txt` — تقرير تحليلي للاستقرار (مرجع فقط، لا يُستخدم للترشيح).

### 4) (اختياري) إشعارات تيليجرام أثناء البحث
اضبط متغيّرات البيئة:
```
export TELEGRAM_TOKEN="توكن بوتك"
export TELEGRAM_CHAT_ID="معرّف الدردشة"
```
عندها تُرسل رسائل النسبة المئوية وتقرير الحالة. إن لم تُضبط، يعمل البحث بلا إرسال.

## متغيّرات البيئة المهمّة (اختيارية، لها قيم افتراضية)

| متغيّر | الافتراضي | المعنى |
|---|---|---|
| `NOVA_ARCHIVE` | `~/crypto_archive` | مجلد بيانات الشموع |
| `NOVA_HOME` | `~/nova_v8_out` | مجلد المخرجات |
| `NOVA_MODE` | `backtest` | `backtest` (لا توجد `live` بعد) |
| `NOVA_START` / `NOVA_END` | فارغ | قصّ نافذة زمنية (مثال `2023-01-01`) |
| `NOVA_REGIME_TF` | `15m` | الإطار الزمني الأعلى للحالة |
| `NOVA_TRIGGERS` | `all` | قائمة محفّزات مفصولة بفاصلة للاختبار اليدوي |
| `NOVA_ONE_SYMBOL` | `1` | معالجة عملة واحدة ثم تحرير الذاكرة |
| `TELEGRAM_TOKEN` / `TELEGRAM_CHAT_ID` | فارغ | إشعارات تيليجرام |

كل المعاملات القابلة للضبط (خروج ATR، حدود الشبكة، وحدة البيتكوين، التكاليف، نافذة
الصدق، التصنيفات، قيم t، المحفّزات...) في **`config.py`** = مصدر الحقيقة الوحيد.

## ضبط المعامل يدوياً ثم تعلّم تلقائي (عند توفّر البيانات)

عندما تُوفّر البيانات التاريخية وتُعلمني:
1. **الخط الأساس:** كل المحفّزات + خروج افتراضي على كل العملات الـ12.
2. **ضبط يدوي لكل متغيّر على حدة.**
3. **مرحلة التعلّم التلقائي** (تحسين عبر الاضطراب / البحث في الشبكة) لأفضل الشرائح.

لتجربة محفّز/مجموعة معيّنة يدوياً:
```
NOVA_TRIGGERS="RSI,EMA" python -m nova_v8 research
```

## ملاحظات صادقة على النتائج

* نتيجة الاختبار الرجعي **تعتمد كلياً على جودة البيانات**؛ البيانات التركيبية في
  `selftest` تُستخدم فقط للتحقّق من خلوّ الكود من الأخطاء، **وليست** مؤشراً على الربحية.
* يطبّق الوثيقة بالحرف: للصفقات الاتجاهية وقف زمني قصير (شمعة واحدة، ربح دون
  عتبة صغيرة) → هذه صفقات سكالبينغ سريعة تتطلب ضبطاً دقيقاً؛
  تُعالج في مرحلة ضبط المتغيّر الواحد (لا تُغيَّر هنا للحفاظ على أمانة الوثيقة).
* المحفّزات تُعامَل كإشارة (rising-edge) تُفتح صفقة عند أول تفعيل، واتجاه الصفقة
  يتبع الحالة (long في الصاعد، short في الهابط)، لتجنّب التداول المتكرّر بلا داعٍ.
* «الاستقرار» في هذه المرحلة تحليليّ فقط (تقرير oracle_stability) ولا يرشّح الصفقات بعد.

## البنية

```
nova_v8/
├── config.py          # كل المعاملات (مصدر الحقيقة)
├── indicators.py      # المؤشرات + مصفوفة الخصائص
├── microstructure.py  # MSS / SFP / FVG
├── regime.py          # تصنيف الحالة (إطار أعلى ← تعيين 1m)
├── triggers.py        # بناء المحفّزات + أحداث الدخول
├── oracle.py          # TruthOracle + مقاطع الحالة
├── execution.py       # Position / ExitEngine (خروج ATR) + التسوية
├── grid.py            # وضع الشبكة السعرية
├── btc_leadlag.py     # وحدة تابعي البيتكوين
├── feeds.py           # قراءة الأرشيف Parquet + مصفوفة/ذاكرة تخزين
├── engine.py          # إعادة التشغيل + المحاسبة + التقارير
├── telegram_notify.py # إشعارات التقدم + تقرير الحالة
├── __main__.py        # واجهة سطر الأوامر
└── tests/selftest.py  # فحص ذاتي ببيانات تركيبية
```
