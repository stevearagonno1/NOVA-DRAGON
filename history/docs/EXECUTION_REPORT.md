# تقرير تنفيذ — NOVA_V8 adaptive_trend sweep (477→1920)

**التاريخ:** 2026-09-12 | **البيئة:** Linux sandbox, Python 3.13.14, pandas 2.2.3, numpy 2.3.5, pyarrow 25.0.1, 2 vCPU / 1.9GB RAM

## ما نُفّذ (حرفياً حسب العقد)
1. استُخرج كود المحرك (28 ملفاً) من الحزمة إلى `~/work/nova_v8/` — **بدون أي تعديل على الكود**.
2. استُخرج ملف التقدم (476 تركيبة) إلى `~/work/sweep_results/adaptive_trend/sweep_train_partial.csv`.
3. نُزّلت الشهور الـ36 من روابط Binance (2023-09 → 2026-08) وبُني `~/work/crypto_archive/BTCUSDT_1m.parquet`:
   **1,578,240 شمعة، صفر دقائق مفقودة**.
4. شُغّل أمر العقد حرفياً من `~/work`:
   ```
   NOVA_ARCHIVE=/home/user/work/crypto_archive python3 nova_v8/sweep_engine.py \
     --strategy adaptive_trend --symbol BTCUSDT \
     --train 2023-09:2024-12 --test 2025-01:2026-08 \
     --out sweep_results
   ```
5. ظهرت علامة النجاح المطلوبة: `▶ استكمال: 476 تركيبة منجزة سابقاً — سيُكمل الباقي فقط`
6. اكتملت الجولة: 1,444 تركيبة تدريب (~8.7 ث/تركيبة، إجمالي ~3.5 ساعة) + فرز + هضبة + 8 تركيبات اختبار. العملية أنهت بـ exit code 0.

## ⚠️ خلل تقني واحد عُثر عليه وعولج (في إعداد البيانات فقط — ليس في كود المحرك)
`fetch_archive.py` المرفق يفترض أن `open_time` بالميكروثانية لكل الملفات (`unit="us"`)،
لكن Binance غيّرت الوحدة: **ملفات ≤ 2024-12 بالملّي ثانية، وملفات ≥ 2025-01 بالميكروثانية**.
النتيجة: نافذة التدريب كاملة (2023-09→2024-12) كانت ستنهار إلى تواريخ 1970 وتفشل عينة التحقق حتماً.
**المعالجة:** سكربت مستقل `~/work/rebuild_archive.py` (خارج حزمة المحرك) أعاد بناء الـparquet
بنفس منطق `build()` مع كشف الوحدة لكل ملف. كود `nova_v8/` لم يُمسّ إطلاقاً.
